# Research focus

This repository is Butson Towers: exact scalar restriction of verified
Butson-related designs, weighted orthogonal sources and certified flat
endpoints. Read `docs/FOUNDATIONS.md` and `docs/SCALAR_REDUCTION.md` first.
Use `docs/RESULTS_SCOPE.md` for the precise scope of a completed result.

- Start from complete sources with exact Gram proofs. Carry the source,
  scalar action, conjugation, trace metric, actual entry alphabet,
  dimension and Gram scale through every restriction.
- Orthogonality is inherited with the transported metric. A Euclidean
  root/sign endpoint additionally requires a verified compatible frame
  and entry test. Never identify the inherited Gram scale with expanded
  order without proving the required equality.
- Weighted intermediate matrices need not be Butson matrices. Preserve
  zeros when reducing weighing or conference designs and state the
  resulting weight.
- Towers may pass through number fields or products of number fields.
  For product algebras retain all factors, multiplicities, trace
  normalizations and reconstruction maps; test the actual final blocks.
- Prefer forward reductions and replayable literal matrix recipes. Keep
  complete sources, incomplete searches and completed outputs distinct.
  Timeouts and necessary-condition survivors prove neither nonexistence
  nor a new matrix.
- Use the active engines listed in `experiments/scalar_lift/README.md`.
  Other retained modules may be dependencies of exact source recipes.
  Do not reopen superseded searches for routine context. Consult a
  historical certificate only to answer a concrete question.
- `.ignore` excludes generated scalar stores from broad searches. Read
  an explicit path or use `rg --no-ignore` when a particular store is
  needed.
- Compare an actual completed endpoint with current primary literature.
  Label it known where a prior construction was located; otherwise use
  new to the best of the author's knowledge after the dated literature
  checks. Keep incomplete work labelled as targets. An infinite existence
  family does not make every member's order new.
- Attribute the 2026 starting reference and older morphism constructions
  as recorded in `docs/FOUNDATIONS.md`. The project name does not claim
  priority for restriction of scalars or for Butson morphisms.
- Preserve frozen construction bundles and their hashes. Put subsequent
  status updates, new outputs and independent audits in separate records.
- Run `./scripts/run_tests.sh` for the repository suite. Use focused
  replay commands from the active engine guide when validating an
  individual source or endpoint.
